# 360 环评 Agent 开发流程

这份模板适合新手照着用。目标不是让流程复杂，而是避免 agent 一次做太多、改乱、难验收。

## 0. 一句话目标

我要做一个 360 环评系统，让组织可以创建评价项目，邀请多人从不同关系维度评价一个人，最后生成可读的反馈报告。

## 1. 开发总原则

每次找 agent 开发前，先确认这 5 件事：

1. 这次只做一个小功能。
2. 我知道这个功能给谁用。
3. 我知道用户完成后的结果是什么。
4. 我知道怎么检查它是否完成。
5. 我允许 agent 修改哪些文件或模块。

## 2. 项目阶段

### 阶段 A：MVP 主流程

目标：先让系统能完整跑一遍。

- 创建评价项目
- 添加被评价人
- 添加评价人
- 发送或生成评价链接
- 评价人填写问卷
- 管理员查看提交状态
- 生成基础报告

### 阶段 B：配置能力

目标：让问卷和评价关系可以配置。

- 评价维度
- 题目管理
- 评分量表
- 评价人关系分类
- 项目模板

### 阶段 C：报告能力

目标：让报告更有解释力。

- 分维度得分
- 自评和他评对比
- 不同关系组对比
- 优势项和待提升项
- 文本反馈摘要

### 阶段 D：权限与安全

目标：保护评价数据。

- 管理员权限
- 评价人匿名
- 提交后不可随意修改
- 报告访问控制
- 数据导出限制

## 3. 每次派任务给 agent 的模板

复制下面这段，按实际情况填空：

```text
项目：360 环评

这次只做：

背景：

用户是谁：

用户要完成什么：

验收标准：
1.
2.
3.

允许修改的范围：

不要做：

完成后请说明：
1. 改了哪些文件
2. 怎么验证
3. 下一步建议
```

## 4. 复杂任务也用简单问法

如果任务变复杂，不要开一套大文档。只让 agent 先回答这 5 个问题：

1. 这个功能给谁用？
2. 用户完成后会看到什么结果？
3. 需要改哪些模块？
4. 哪些地方不能动？
5. 我怎么验收它？

然后再让 agent 一次只实现一个小块。

## 5. 任务池

所有想法先放这里，不马上做。

| 想法 | 价值 | 难度 | 状态 |
| --- | --- | --- | --- |
| 创建评价项目 | 高 | 中 | 待做 |
| 评价链接填写问卷 | 高 | 中 | 待做 |
| 基础报告 | 高 | 中 | 待做 |
| AI 总结文字反馈 | 中 | 高 | 暂缓 |

## 6. 新手最容易踩的坑

- 一次让 agent 做太多。
- 需求没写清楚就开始写代码。
- 没有验收标准，只看“好像完成了”。
- 不区分 MVP 和以后再做。
- 忘记匿名和权限是 360 环评的核心风险。
- 不记录重要决定，后面自己也忘了为什么这么做。

## 7. 推荐第一批任务

先从这 5 个任务开始：

1. 写清 360 环评 MVP 的用户角色和主流程。
2. 定义核心数据对象：项目、被评价人、评价人、问卷、提交、报告。
3. 做项目列表和创建项目。
4. 做评价人填写问卷的最小页面。
5. 做一个最基础的报告页面。

## 8. 每轮结束记录

每次 agent 做完，把下面几项记下来：

```text
日期：
本轮任务：
完成结果：
验证方式：
发现的问题：
下一步：
```
